# 15 — AI 代码生成控制规范

- 版本：v1.0

---

## 1. 模块目标

约束 AI（即我）在 PointCloudROIManager 项目下每次生成代码的**输出格式、推进节奏、review 流程**。本规范是"AI 与人类工程师之间的契约"，不是给人看的，是给 AI 自己执行的。

## 2. 工业应用场景

- 产线代码不允许 AI 一次性吐 2000 行就跑
- 每个模块必须分步交付，等人类确认后再进下一步
- 代码质量靠流程兜底，不靠 AI 自觉

## 3. 架构位置

本规范是开发流程约束，叠加在所有模块之上。

## 4. 输入输出定义

- 输入：人类下达的"做 06_ROIExtractor"这类指令
- 输出：六段式结构化交付（见 §7）

## 5. 数据结构

每次 AI 交付必须按以下顺序输出，缺一段视为不合格：

1. **设计说明**：本步骤要解决什么问题、与上一步的关系
2. **文件结构**：新增 / 修改哪些文件，每个文件的行数预估
3. **`.h` 头文件**：完整内容
4. **`.cpp` 实现文件**：完整内容
5. **测试代码**：GoogleTest 用例
6. **编译说明**：CMakeLists 改动 + 预期编译输出 + 已知 warning

## 6. 类设计（AI 行为约束）

### 6.1 强制顺序

AI 必须严格按 `00_Master_Control.md §8` 的 Step 01–08 推进。跳步 = 不合格。

### 6.2 禁止行为

- 一次性生成所有模块代码
- 修改未被指令点名的文件
- 在实现里加注释以外的"贴心"功能（如顺手加个 GUI）
- 把 PCL / JSON 类型泄漏进公共头
- 用 `using namespace std` / 裸 new / 全局变量
- 省略测试代码
- 省略 CMakeLists 改动

### 6.3 必须行为

- 每一步先列设计说明，再写代码
- 任何 magic number 用常量名
- 错误字符串结构化（字段 / 期望值 / 实际值）
- 性能热点函数加 `// hot path` 注释
- 单元测试命名 `ModuleName_Scenario_Expectation`

## 7. 接口设计（交付模板）

AI 每次响应必须按以下模板输出：

```markdown
## 设计说明
（这段做什么、依赖上一步的哪些类型、输出给谁用）

## 文件结构
- include/xxx.h     (新增, ~80 行)
- src/xxx.cpp       (新增, ~200 行)
- tests/test_xxx.cpp (新增, ~120 行)
- CMakeLists.txt    (修改: 加 xxx target)

## 头文件
```cpp
// 完整内容
```

## 实现
```cpp
// 完整内容
```

## 测试
```cpp
// GoogleTest 用例
```

## 编译说明
- 依赖：PCL::common / PCL::io / PCL::octree
- 新增 target：xxx
- 预期 warning：无
- 已知风险：xxx
```

## 8. 算法流程（人类 review 流程）

```
AI 交付六段
    ↓
人类 review：
  ├── 设计说明是否解决了问题
  ├── 头文件是否泄漏 PCL / JSON
  ├── 实现是否符合 14_Code_Standard
  ├── 测试是否覆盖正常 / 异常 / 性能
  └── 编译说明是否真实可复现
    ↓
人类回复：
  ├── "通过" → AI 进下一步
  ├── "改 X" → AI 只改 X，不重写其他部分
  └── "回退到 Step N" → AI 从 N 重来
```

## 9. 异常处理（AI 行为异常）

| 异常 | 处理 |
| --- | --- |
| AI 一次性贴了 1000 行 | 人类直接打回，要求拆成 Step 粒度 |
| AI 改了未被点名的文件 | 人类打回，AI 必须还原 |
| AI 编译失败 | AI 必须自己跑 `build_operator.bat` 验证后再交付，不允许"我觉得能编过" |
| AI 输出缺测试 | 打回补齐 |

## 10. 测试要求

- AI 交付前必须本地跑过 `ctest -L unit`（至少 Parser / Geometry 部分）
- 性能用例 AI 自己跑一次，把耗时写进"编译说明"
- 不允许写"这段测试留待后续"

## 11. AI 实现要求（自我检查清单）

每次交付前 AI 自查：

- [ ] 头文件是否出现 `pcl::` / `nlohmann::` / `cv::`？出现就打回
- [ ] 是否用了 `using namespace std`？是就打回
- [ ] 是否有裸 `new` / `delete`？是就打回
- [ ] 错误字符串是否结构化？否就补
- [ ] 测试是否覆盖正常 + 异常 + 性能？否就补
- [ ] CMakeLists 是否同步更新？否就补
- [ ] 单位注释是否齐全？否就补
